<p>选地址这件事上，误导往往来自几个听起来很顺的词：独享、纯净、专线。词本身没错，错在把它们当成同一个维度的形容词。同一个"独享"可以指地址不与他人共用，也可以只指通道不与他人共用，出口地址照样在几十个人手里轮换。这篇专门纠几个常见的偏差：哪些直觉是对的，哪些只在特定条件下成立，以及怎么用三两个公开可查的证据把它们分开。</p>

<h2>一、先看四个流传很广的直觉判断</h2>
<p>这四个判断在群里、在销售话术里出现频率极高，共同点是"听起来有道理，但缺了前提条件"。把它们摆出来本身就能省下不少试错成本。</p>
<h3>直觉一：独享就是速度快</h3>
<p>独享解决的是占用冲突，不解决带宽总量。一条 20Mbps 的独享地址，跑满就是 20Mbps，再独享也不会变成 100M。速度取决于上游带宽和线路质量，和是否独享是两个维度。</p>
<h3>直觉二：独享就是干净</h3>
<p>干净指的是历史记录。一条刚被别人用作批量注册的地址，转手给你做独享，它依然不干净。地址不与他人"同时"使用，和地址"历史上"被怎么用，是两件独立的事。</p>
<h3>直觉三：共享就一定差</h3>
<p>共享的代价是行为耦合，不是必然劣化。低流量、短任务、对身份连续性没有要求的场景，共享池的性价比往往更高；真正吃亏的是把需要长期固定身份的业务放在共享池里。</p>
<h3>直觉四：说"专线"就一定独占</h3>
<p>专线描述的是接入方式，不等于地址独占。市场上不少"专线共用"的方案，实际是把一条上游线路切分转售，出口地址池由多个客户共用，价格便宜但地址会漂。</p>

<h2>二、误解一：独享管的是占用，不管带宽</h2>
<p>把这两件事分开之后，选型会清楚很多：需要大带宽就买带宽，需要稳定身份就买地址独占，两者可以分别付费，不必捆在一个套餐里选择。</p>
<h3>带宽看的是峰值而不是均值</h3>
<p>接口调用用不满带宽，但如果同时跑文件上传、日志回传，峰值会突然拉高。按峰值需求乘 1.5 选带宽，比按平均流量选更稳妥。测法很简单：用并发请求把通道打满，看实际吞吐能到多少，别只看宣传数字。</p>
<h3>占用冲突的表现是"忽快忽慢"</h3>
<p>共享带宽时，别人的高峰就是你的低谷。特征是同一时段内速度波动极大，P95 远高于中位数。遇到这种曲线，先确认是不是共享，再谈优化。</p>

<h2>三、误解二：共享出口真正的代价是行为耦合</h2>
<p>共享本身不是问题，"和谁共享"才是问题。同一条出口上如果有人在跑高频脚本，你的正常调用在平台侧看来就是这条地址整体行为的一部分。</p>
<h3>耦合怎么传导到你身上</h3>
<p>出口地址的请求频率、时段分布、目标服务集中度，都是被一起观察的。别人的异常节奏会抬高这条地址的整体可疑度，你的请求虽然规矩，也难免被归到同一组。这不是技术故障，却比技术故障更难解释。</p>
<h3>可控的做法是"能固定就固定"</h3>
<p>对需要长期保持身份的业务，选择可以固定会话的出口，并且确认固定的是地址而不只是连接。判断方法很直接：隔几个小时再请求一次回显地址的接口，看返回的地址是否一致。</p>

<h2>四、误解三：把转售包装成专线，是价格差的主要来源</h2>
<p>同样写着专线，报价能差三倍，多数情况不是谁在做慈善，而是转售层级不同。层级越多，中间环节越多，你能拿到的地址池越浅，稳定性也越难保证。</p>
<h3>问清"这条线的上游是谁"</h3>
<p>正规供应商能说清上游运营商与接入方式，含糊其辞、只强调"资源独享"却拿不出拓扑说明的，多半是转售。这不是说转售一定不能用，而是要知道自己在为什么付费。</p>
<h3>价格低到反常时，先算共享率</h3>
<p>一条地址的成本是相对固定的，售价远低于同行时，通常意味着同一条地址卖给了更多人，或者带宽被严重超售。用一段时间的实测吞吐和成功率曲线，可以反推真实余量。</p>

<h2>五、纠正之后，按"谁在用"重新分类地址</h2>
<p>与其纠结独享还是共享，不如按使用人数和地址漂移程度分类。这个维度直接对应业务体验，也更容易在合同里写清楚。</p>
<h3>四类地址的适用边界</h3>
<p>单人独占、固定不变，适合长期账号与正式业务；小池共用、可固定会话，适合中等规模的多项目；大池轮换，适合采集类短任务；端口级共享，只适合对身份无要求的探测。四类的价格与风险递增方向不同，别用一套预算硬套。</p>

<h3>写进合同的三个数字</h3>
<p>同池客户数上限、单地址并发上限、地址变更的提前通知时间。这三个数字比任何形容词都实在，也最容易在出问题时成为依据。愿意写的供应商，通常对自己的资源有把握。</p>

<h2>常见问答</h2>
<h3>共享出口一定会导致调用失败吗？</h3>
<p>答：不一定。失败通常来自并发被打满、地址被整体降权或线路拥塞，而不是共享这个事实本身。低峰期、低频次的调用在共享池上往往跑得很稳，问题集中出现在高峰和高频场景。</p>
<h3>怎么判断自己的出口是不是被别人共用？</h3>
<p>答：间接判断为主。看同一地址在不同时段的延迟与成功率波动是否和你的业务量无关；看回显地址是否在你没有操作时发生变化；直接问供应商同池客户数，并要求写入合同。</p>
<h3>独享地址还需要做纯净度检查吗？</h3>
<p>答：需要，而且更重要。独享意味着这条地址的所有行为都会记在你名下，历史上遗留的问题也会一起继承。拿到地址先查 ASN、类型标签和近 90 天滥用记录，再投入使用。</p>
<h3>便宜的共享池能不能先用来跑测试？</h3>
<p>答：可以，但测试结论要慎用。共享池的表现和正式环境差异较大，用它的成功率去推断上线后的表现，容易得出过于乐观或过于悲观的结论。测试阶段就尽量贴近正式环境的出口类型。</p>
